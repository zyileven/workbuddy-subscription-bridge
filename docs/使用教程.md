# 从零执行与 WorkBuddy 使用教程

项目目录：`~/workbuddy-subscription-bridge`。

如果使用 Docker，请先按 [Docker 启动与授权](Docker.md) 操作；本文以下命令对应直接使用 Node.js 的启动方式。

这份教程对应本项目当前的实现：你在浏览器中给本地桥接服务授权，
WorkBuddy 使用本机密钥请求它，桥接服务再用 OAuth 令牌调用 OpenAI。
代码和本地模拟测试已经准备好；你的真实账号资格、实际套餐扣减和 WorkBuddy
客户端兼容性，仍需执行本文的验收步骤确认。

## 一、检查运行环境

打开 macOS 终端，执行：

```bash
cd ~/workbuddy-subscription-bridge
node --version
```

要求 Node.js 22 或以上。如果提示找不到 `node`，或版本低于 22，先安装或升级 Node.js。
本项目只使用 Node 标准库，**不需要执行 `npm install`**。

查看命令列表：

```bash
node src/cli.mjs help
```

服务运行时需要电脑保持开机，能够访问 OpenAI 的登录和模型接口。
本教程使用前台运行方式，终端退出或电脑重启后需要重新启动服务。

## 二、首次初始化并登录

在同一个终端依次执行：

```bash
node src/cli.mjs init
node src/cli.mjs login
```

`init` 创建项目自己的安装标识和本机密钥。
`login` 会打开系统浏览器，等待你完成登录并授权套餐使用。

在浏览器中：

1. 确认页面属于 OpenAI 的登录流程。
2. 登录你准备使用的 ChatGPT 账号，检查所选工作区。
3. 检查应用名称为 `WorkBuddy Local Subscription Bridge`。
4. 根据页面提示授权使用 ChatGPT 套餐。
5. 完成后返回终端。

成功时，终端应显示类似：

```json
{
  "connected": true,
  "plan_usage_enabled": true
}
```

这表示登录和权限检查通过，还不等于模型请求已成功。
如果 `plan_usage_enabled` 为 `false`，先检查浏览器中的授权选择与账号可用权限，
不要继续将其当作已经可用的模型配置。

默认回调地址是 `http://127.0.0.1:1455/auth/callback`。
如果 1455 端口被占用，可以换一个本机端口：

```bash
node src/cli.mjs login --callback-port 1456
```

浏览器没有自动打开时，可以让终端显示登录链接：

```bash
node src/cli.mjs login --no-open
```

在本机浏览器打开终端给出的链接，保持登录命令运行直到回调完成。
不要将回调主机名改成 `localhost`，也不要将登录链接发给其他人。

## 三、查看账号状态与可用模型

```bash
node src/cli.mjs status
node src/cli.mjs models
```

`models` 返回当前授权账号可见的模型，例如下面这种结构：

```json
[
  {
    "slug": "这里是账号实际返回的模型标识",
    "name": "这里是显示名称"
  }
]
```

复制你准备使用的 `slug`。后续 WorkBuddy 的“模型名称”填这个值，
不要填写显示名称，也不要根据其他客户端的模型列表猜测。

模型列表成功只证明发现接口可用。接下来发送一个小请求验证实际推理权限：

```bash
node src/cli.mjs verify --model YOUR_MODEL_SLUG
```

**把 `YOUR_MODEL_SLUG` 替换成刚才复制的真实 slug。**
这一步会发送一次真实模型请求，产生相应的套餐或已授权额度用量。

成功时会显示模型回复，以及收到 `response.completed` 的提示。
然后到 ChatGPT 设置 → 用量，核对该应用记录和实际扣减情况。
这一步不能证明与官方 Codex 客户端的全部权益、额度和功能完全相同。

如果出现账号不符合资格、没有模型权限或额度限制，先按错误代码处理，
不要反复请求，也不要用其他账号的凭据替代。

## 四、取得 WorkBuddy 要填写的本机密钥

```bash
node src/cli.mjs key
```

复制命令输出的完整字符串，稍后填入 WorkBuddy 的 API Key 输入框。

这个密钥只用于访问本机桥接服务；它不是 OpenAI API Key，也不是 OpenAI
access token。**不要将 ChatGPT 密码、OpenAI access token 或 refresh token
填写到 WorkBuddy。**

## 五、启动服务并保持终端运行

```bash
node src/cli.mjs serve
```

看到类似输出即表示本机监听已启动：

```text
Bridge: http://127.0.0.1:8787/v1
```

保持这个终端打开。后面称它为“服务终端”。
服务只监听本机 `127.0.0.1`，不提供给局域网或公网访问。

如需检查监听，另开一个终端执行：

```bash
curl http://127.0.0.1:8787/health
```

预期结果：

```json
{"status":"ok","service":"workbuddy-subscription-bridge"}
```

`health` 仅检查本机服务，不会调用 OpenAI，也不能替代第三步的真实推理验收。

## 六、在 WorkBuddy 中添加自定义主模型

进入 WorkBuddy：设置 → 模型 → 添加模型，选择“自定义”供应商。
不同版本的界面文字可能稍有差异。

| 配置项 | 应填写的内容 |
| --- | --- |
| 接口地址 | `http://127.0.0.1:8787/v1/chat/completions` |
| API Key | 第四步 `key` 命令输出的本机密钥 |
| 模型名称 | 第三步 `models` 命令返回的真实 slug |
| 自定义协议 | 开启，按填写的完整 URL 请求 |
| 工具调用 | 开启 |
| 图片输入 | 仅在所选模型支持并且需要时开启 |
| 思考强度 | 先保留默认；需要设置时使用所选模型支持的档位 |

如果你的版本明确要求填写 Base URL 而非完整接口地址，则填写
`http://127.0.0.1:8787/v1`，由客户端补 `/chat/completions`。
不要让最终地址重复出现两次 `/chat/completions`。

如果界面提供“测试连接”，先执行测试，再保存。
随后在对话的模型选择器中**明确选中刚才添加的自定义模型**；不要用 Auto 模式
来判断是否经过桥接。

## 七、完成两项 WorkBuddy 验收

### 1. 普通问答

新建对话，选中自定义模型，输入：

```text
请只回复：WorkBuddy 本地桥接问答成功。
```

确认能收到完整回复且没有连接错误。

### 2. 只读工具任务

在另一个终端准备一个专用测试目录和测试文件：

```bash
cd ~/workbuddy-subscription-bridge
mkdir -p work/acceptance
printf 'bridge acceptance sample\n' > work/acceptance/sample.txt
```

在 WorkBuddy 中把这个目录作为任务可访问的工作目录，或根据其权限提示允许访问。
随后输入：

```text
请列出 ~/workbuddy-subscription-bridge/work/acceptance
目录中的文件，然后读取 sample.txt 并告诉我内容。只读取，不修改任何文件。
```

确认它能完成“调用工具 → 执行工具 → 回传结果 → 继续回复”的过程。
普通聊天成功不足以证明 Agent 的多轮工具调用兼容。

完成后，再去 ChatGPT 设置 → 用量检查应用记录。只有账号授权、真实推理、
WorkBuddy 问答和工具任务都通过，才可以认为这台电脑上的实际使用路径已完成验收。

## 八、日常使用、停止与重启

以后使用时，一般不需要每次重新登录：

```bash
cd ~/workbuddy-subscription-bridge
node src/cli.mjs serve
```

保持服务终端运行，在 WorkBuddy 中选择自定义模型即可。
令牌接近过期时由桥接服务刷新；如果刷新失败并要求重新登录，停止服务后重新运行
`login`，再启动服务。

停止服务：在服务终端按 **Ctrl+C**。
停止服务不会自动退出账号，也不会自动撤销授权。
电脑重启或终端关闭后，重新执行 `serve`。

8787 被占用时：

```bash
node src/cli.mjs serve --port 8788
```

同时把 WorkBuddy 接口地址改成
`http://127.0.0.1:8788/v1/chat/completions`。

要撤销授权并清除本地令牌，先停止服务，再执行：

```bash
node src/cli.mjs logout
```

撤销失败时程序会保留令牌以便重试；也可以在 ChatGPT 设置里断开该应用。

## 九、账号数据保存在什么位置

默认保存在：

```text
~/workbuddy-subscription-bridge/.local/
```

该目录包含安装标识、本机密钥和 OAuth 凭据。目录权限为 0700，文件权限为 0600。
不要提交到 Git，不要打包分享。本项目 `.gitignore` 已排除默认 `.local/`。

一个 data-dir 对应一个账号注册。更换账号时使用不同的数据目录，并在每条命令中
保持同一个 `--data-dir`。例如在项目内部使用已被忽略的目录：

```bash
node src/cli.mjs login --data-dir ./.local/second-account
node src/cli.mjs models --data-dir ./.local/second-account
node src/cli.mjs key --data-dir ./.local/second-account
node src/cli.mjs serve --data-dir ./.local/second-account --port 8788
```

第二个账号也有自己的本机密钥。WorkBuddy 配置要同时匹配端口、密钥和模型名称。

## 十、常见问题

| 现象或错误 | 检查与处理 |
| --- | --- |
| `node: command not found` | 安装 Node.js 22 以上并重新打开终端 |
| WorkBuddy 连接被拒绝 | 检查服务终端是否还在运行、端口是否一致，执行 `/health` 检查 |
| `invalid_local_key` | 重新执行 `key`，确认 WorkBuddy 填的是同一 data-dir 的本机密钥 |
| `login_required` | 运行 `login` 并完成浏览器回调 |
| `plan_usage_not_granted` | 重新授权套餐使用；仅身份登录不够 |
| `subscription_sharing_user_not_eligible` | 检查账号、工作区和资格；不能通过重试解决 |
| `subscription_sharing_usage_limit_exceeded` | 暂停请求，检查 ChatGPT 用量页和应用限额 |
| `unsupported_request` | 查看错误中的 `param`；WorkBuddy 发来了原型不支持的参数或内容 |
| `invalid_origin` | 客户端发送了浏览器 Origin；该客户端路径需要进一步适配，当前原型会拒绝 |
| `invalid_upstream_content_type` | 上游未返回预期 SSE，检查网络、代理和接口响应 |
| `truncated_stream` / `upstream_timeout` | 请求没有完整结束；检查网络，不要当作成功回复 |
| `credential_store_busy` | 检查是否存在另一个登录/刷新进程；确认无进程使用后才处理残留锁 |
| 普通问答可以，工具调用失败 | 保留具体错误和脱敏后的消息结构，按第七步重现；不能据此宣称完整 Agent 兼容 |

本项目不会在推理失败时自动改用 API Key 计费，也不会自动重试模型请求。
流式已经开始后发生错误，可能仍显示 HTTP 200；应检查 SSE 错误以及是否收到
成功结束标记。不同 WorkBuddy 版本对这种错误的显示方式需要实际验收。

## 十一、开发者测试与已知范围

在项目根目录运行：

```bash
npm test
```

本地测试使用合成凭据和模拟上游，不会登录真实账号或消耗套餐。
独立的 Postman HTTP 模拟步骤见 [postman/README.md](../postman/README.md)，
既有验证记录见 [VALIDATION.md](../VALIDATION.md)。

实现范围见 [README.md](../README.md) 和 [接口合同](../CONTRACT.md)。
当前原型支持文本、用户图片输入转换、函数工具调用和流式输出；不支持所有高级
参数或托管工具，也没有缓存和重放完整 reasoning 状态。输出预算等不支持的参数
会按合同移除，因此 WorkBuddy 的某些输出长度设置不会在上游生效。

本文仅说明这个个人本地原型的执行方式，不代表 OpenAI 或腾讯已认证这套组合。
真实模型、额度和权益以账号授权和用量页为准。
